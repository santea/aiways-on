# AIways On — 웹 화면 디자인 요구사항

> 본 문서는 화면에 **표시되어야 하는 정보**만 추려 정리한 디자인 요구사항이다. 내부 구조(API 엔드포인트, DB 스키마, K8s 매니페스트, n8n 워크플로우, 코드)는 배제한다.
> 특히 **SDLC 진행 이력, 장애 대응, 자체개선 Flow를 애니메이션으로 표현**하는 요구사항을 별도 장(§6)에서 강조한다.

---

## 1. 전체 화면 목록 및 접근 권한

| 경로 | 페이지 | 권한 | 표시 요약 |
|------|--------|------|-----------|
| `/login` | 로그인 | 공개 | "Sign in with GitHub" 버튼 |
| `/` | 대시보드 | user / admin | 진행 현황 카드 + SR 목록 |
| `/register` | SR 등록 | user | 신규 SR 등록 폼 |
| `/requests/[id]` | SR 상세 | user(본인) / admin(전체) | 단계 진행 표시 + 채널·Pod·GitHub + 단계 이력 + 액션 |
| `/incidents` | 장애 대응 | user / admin | 장애 목록 + 상태별 집계 |
| `/incidents/[id]` | 장애 상세 | user(읽기) / admin(승격·종결) | 상태 레일 + 개요·증상 + 분석 산출물 |

| `/admin/repos` | Repo 관리 | admin | GitHub Repo 등록·설정 |

| `/admin/memory-tokens` | MCP 토큰 관리 | admin | 토큰 발급·폐기 |

## 2. 디자인 시스템

화면 시각 규칙만 정의한다. 코드 토큰명은 참고용.

### 2.1 핵심 원칙

| 규칙 | 내용 |
|------|------|
| **No Top Nav** | 상단 네비게이션 바 없음. 사이드바에 모든 메뉴 통합 |
| **No-Line** | 표·카드 구분을 테두리(border) 없이 `bg-surface-container` 계층 차이(배경색 명도)로만 표현 |
| **색상 토큰** | 의미적 토큰만 사용. raw hex 사용 금지 |
| **신규 색 토큰 도입 금지** | accent 등급 체계 재사용 |

### 2.2 색상 토큰 (의미적)

| 토큰 | 용도 |
|------|------|
| `text-on-surface` | 기본 텍스트 |
| `text-on-surface-variant` | 보조 텍스트, 대기·중성 상태 |
| `bg-surface-container` | 카드/표 배경 (계층별 명도 차이) |
| `bg-sidebar-active` | 사이드바 활성 항목 배경 |
| accent | 진행 중 상태 |
| success accent | 완료·성공 상태 |
| warning accent | 경고·사람 리뷰 대기 상태 |
| error accent | 실패·치명 상태 |
| Cyan | 사이드바 active blade 글로우 |

### 2.3 타이포그래피

| 토큰 | 폰트 | 용도 |
|------|------|------|
| `font-headline` | Manrope | 타이틀 |
| `font-body` | Inter | 본문 |
| `font-mono-id` | JetBrains Mono | SR 번호·GitHub username·버전 등 식별자 |
| `label-tech` | 10px uppercase | 섹션 헤더, 상태 배지 라벨 |

### 2.4 사이드바 Active 스타일

- 좌측 **4px Cyan blade** 표시
- `bg-sidebar-active` 배경
- `box-shadow: var(--shadow-glow-active)` 글로우 효과

## 4. 화면별 표시 정보

### 4.1 로그인 (`/login`)

| 요소 | 내용 |
|------|------|
| 버튼 | "Sign in with GitHub" |
| 로그인 방식 | GitHub OAuth — 클릭 시 GitHub 인증 → 콜백 → 대시보드 이동 |
| 세션 | 로그인 후 제출자 정보(이름·이메일·GitHub username) 자동 채움 |

**진행 현황 카드** (클릭 시 해당 상태로 필터):

| 카드 | 상태 조건 | 색상 |
|------|-----------|------|
| 진행 | non-terminal (1~5, 7) | accent |
| 대기 | `0_QUEUED` | 보조 텍스트(중성) |
| 완료 | `8_COMPLETED` | success accent |
| 실패 | `X_FAILED` / `X_STOPPED` | error accent |

**SR 목록 테이블**:

| 컬럼 | 내용 | 서식 |
|------|------|------|
| 요청 번호 | `requestNo` (SR 상세 링크) | `font-mono-id` |
| 제출자 | `submitter` | — |
| 시스템 | `requestSystem` | — |
| 상태 | `status` | 상태 배지 |
| 요청일 | `createdAt` | — |

> 상태 필터, 검색(번호/제출자), 페이지네이션 지원. user는 본인 SR만, admin은 전체 SR 조회.

**개발 서브스테이지** (④ 개발 중일 때만 표시):

| 서브스테이지 | 표시 상태 |

| `code_review` | ✅ / 🔵 / ⚪ |
| `security_review` | ✅ / 🔵 / ⚪ |

**Slack 채널**: requirements / design / dev 3개 채널, 각각 활성/아카이브됨 상태 표시

**Pod 상태**: Pod 이름, 실행 상태(RUNNING 등), 헬스체크 결과

**GitHub**: Issue 번호·Repo, PR 번호·Repo, open/closed 상태

**단계 이력** (테이블):

| 컬럼 | 내용 |
|------|------|
| 전이 | `이전 → 이후` (예: `1→2`) |
| 시각 | 전이 시각 |
| 주체 | 수행한 agent |

**웹 터미널** (Pod 내 Claude Code CLI 접근):

| 요소 | 내용 |
|------|------|
| 출력 영역 | 실시간 stdout/stderr 스트리밍 표시 (SSE) |
| 입력 | 명령어 입력 + 전송 (읽기 전용 모드 시 차단) |
| 토글 | 열기/닫기 |

**단계별 액션 버튼** (현재 상태에 따라 활성화):

| 상태 | 버튼 |
|------|------|
| `7_DEV_SERVER_TEST` | 테스트 진행 / 재시도 / 재개발 |
| non-terminal | 중지 (admin 권장) |
| terminal | (버튼 없음) |

## 6. SDLC 파이프라인 Flow & 애니메이션 ⭐

> 사용자 핵심 요청: **SDLC 진행 이력, 장애 대응 등 구동되고 있는 것을 애니메이션으로 표현하고, Flow를 그려 진행 과정을 시각화.**
> 본 장은 각 파이프라인의 단계 흐름과, 화면에서 **애니메이션으로 표현해야 할 진행 상태**를 정의한다.

### 6.1 세 가지 파이프라인 프로파일

SR은 3종 파이프라인 프로파일 중 하나로 동작한다. 화면에서는 동일한 상태 머신을 공유하되 진입 경로와 채널 수가 다르다.

| 프로파일 | 진입 경로 | 채널 | 특징 |
|---------|----------|------|------|
| **기능 개발** (`feature`) | 사용자 SR 등록 UI | requirements + design + dev 3개 | `1 → 2 → 3 → 4 → 5 → 7 → 8` 전체 경로 |
| **장애 대응** (`incident`) | 장애 자동 승격 | **dev 1개만** | 요구사항·설계 스킵, 큐 우선권 |
| **자체개선** (`improvement`) | CronJob 주기 스캔 | **dev 1개만** | 요구사항·설계 스킵, 읽기 전용, 큐 최하위 |

### 6.2 기능 개발 파이프라인 — 단계 전이 Flow

**7개 정상 단계 + 2개 예외 상태** (배포 단계 `6_DEPLOYED`는 제거됨):

```
① 등록 ──▶ ② 요구사항 ──▶ ③ 설계 ──▶ ④ 개발 ──▶ ⑤ 배포준비 ──▶ ⑦ 테스트 ──▶ ⑧ 완료
 REGISTERED    REQUIREMENTS     DEV_DESIGN     DEV_IN        READY_FOR      DEV_SERVER     COMPLETED
               _IN_PROGRESS     _IN_PROGRESS   _PROGRESS     _DEPLOY        _TEST

                                                                   │
                              ┌──── 재개발 역전이 (7 → 4) ◀─────────┘
                              ▼

예외:  X_STOPPED (사용자 중지)   X_FAILED (실패 → 보상 트랜잭션)
```

**SR 상세의 "단계 진행 표시" 애니메이션 요구사항**:

| 요소 | 표현 |
|------|------|
| 단계 노드 | ①~⑧ 원형/캡슐 노드, 단계명 표시 |
| 완료 단계 | ✅ 체크 + success accent 강조 |
| 현재 단계 | ▲ 표식 + accent 강조 + **펄스/글로우 애니메이션** (진행 중임을 나타냄) |
| 미도달 단계 | ⚪ 대기 상태, 보조 텍스트 색 |
| 전이 화살표 | 완료된 전이는 실선 + 애니메이션(채워짐), 미도달 전이는 점선 |
| 현재 단계명 | "현재: ④ 개발 중" 텍스트 강조 |

**단계 이력 (테이블)** — 진행 이력 타임라인:

| 전이 | 시각 | 주체 |
|------|------|------|
| `1→2` | 2026-09-01 10:00 | n8n-agent |
| `2→3` | 2026-09-01 14:00 | n8n-agent-fb |
| `3→4` | 2026-09-01 18:00 | n8n-agent-fb |

> **애니메이션**: 새 이력이 추가될 때 상단에 슬라인-인 등 부드러운 등장 애니메이션.

### 6.3 개발 서브스테이지 (DevSubStage) — ④ 개발 내부 Flow

`4_DEV_IN_PROGRESS` 단계에서 4개 서브스테이지가 순차 진행된다:

```
① dev ──▶ ② qa ──▶ ③ code_review ──▶ ④ security_review
 ✅ 완료      ✅ 완료     ▲ 진행 중         ⚪ 대기
```

**애니메이션 요구사항**:

| 요소 | 표현 |
|------|------|
| 서브스테이지 노드 | ①~④ 스텝 표시, 이름 라벨 |
| 완료 | ✅ + success |
| 진행 중 | 🔵 + accent + **펄스 애니메이션** |
| 대기 | ⚪ 보조 색 |
| 진행 화살표 | 현재 서브스테이지로 **점진적 채움** 애니메이션 |

> **실시간 갱신**: 10초마다 상세 재조회로 서브스테이지 진행 상태 자동 갱신 — 상태 변화 시 부드러운 전환 애니메이션.

### 6.4 장애 대응 파이프라인 — 5단계 상태 레일 Flow

장애는 5단계로 진행되며, 장애 상세 화면의 **상태 레일**로 시각화한다:

```
DETECTED ──▶ SR_PROMOTED ──▶ TRIAGING ──▶ GUIDE_READY / PATCH_PROPOSED ──▶ RESOLVED
 (수집)        (승격)         (분석)          (산출)                       (종결)
```

**5단계 정의**:

| 단계 | 이름 | 주체 | 상태 | 표시 |
|------|------|------|------|------|
| 1 | 수집 (ingest) | 모니터링 / admin UI | `DETECTED` | 보조 텍스트 |
| 2 | 승격 (promote) | Portal | `SR_PROMOTED` | accent |
| 3 | 분석 (analyze) | Pod agent | `TRIAGING` | accent |
| 4 | 산출 (report) | Pod agent | `GUIDE_READY` / `PATCH_PROPOSED` | accent / warning |
| 5 | 종결 (resolve) | 사람 (admin) | `RESOLVED` | success |

**상태 레일 애니메이션 요구사항**:

| 요소 | 표현 |
|------|------|
| 레일 | 8개 상태 노드를 가로로 나열 (Progress 바 기반) |
| 현재 상태 | cyan blade 강조 + **펄스/글로우 애니메이션** |
| 완료 상태 | success accent, 실선 연결 |
| 미도달 상태 | 점선, 보조 색 |
| 산출물 도착 | `TRIAGING`에서 새 분석 산출물이 도착하면 산출물 영역에 **슬라이드-인 애니메이션** |
| 실시간 폴링 | 10초 간격 재조회 — 상태 전이 시 레일이 부드럽게 이동 |

**장애 상세 분석 산출물** (상태 레일 하단, 펼침 가능):

| 산출 종류 | 배지 | 내용 |
|-----------|------|------|
| GUIDE | [GUIDE] | 대응 가이드 (근본 원인·즉시 조치·완화·재발 방지) |
| PATCH | [PATCH] | 코드 수정 PR 링크 |
| 배제 | [배제] | 배제한 가설 기록 |

> 각 산출물은 생성 시각과 함께 표시, 펼침 시 마크다운 본문 렌더.

### 6.5 자체개선 파이프라인 — 5단계 Flow

등록된 repo를 주기 스캔해 개선점(finding)을 발굴하고 승격하는 파이프라인:

```
① 선별 ──▶ ② 스캔 SR 승격 ──▶ ③ 분석 ──▶ ④ finding 등록 ──▶ ⑤ 승격/반려
 (CronJob)   (intake)          (Pod)      (upsert)          (사용자)
 pending     1_REGISTERED       실행 중    proposed          accepted/rejected
                                                       → SR 승격 / 규정 승격
```

**5단계 정의**:

| 단계 | 주체 | 산출 | 상태 |
|------|------|------|------|
| 1. 선별 | CronJob → Portal | 스캔 회차 (`pending`) | 대기 |
| 2. 스캔 SR 승격 | Portal | SR (`1_REGISTERED`) | 승격 중 |
| 3. 분석 | Pod (Claude Code) | `improvement-report.md` | 실행 중 |
| 4. finding 등록 | Pod → Portal | finding 일괄 등록 (`proposed`) | 미검토 |
| 5. 승격/반려 | 사용자·admin | SR 승격 / 규정 승격 / 반려 | 채택/반려 |

**스캔 상세 화면 애니메이션 요구사항**:

| 요소 | 표현 |
|------|------|
| 스캔 메타 카드 | repo, systemKey, baseCommitSha, 연결 SR, finding 수, **소요 시간** |
| 진행률 바 | `running` 상태일 때 **경과 시간 / 타임아웃 Progress 바** (실시간 증가 애니메이션) |
| category 탭 | 7개 category (security, architecture, dx 등), 건수 0인 탭 비활성 |
| finding 행 | severity 배지 + 제목 + 파일 + 반복 수 + 상태 배지 |
| 채택/반려 | 버튼 클릭 시 상태 배지가 부드럽게 전환 (proposed → accepted) |
| 승격 | accepted finding의 [SR 승격]/[규정 승격] 버튼 → 확인 다이얼로그 |

### 6.6 실시간 진행 갱신 — 공통 애니메이션 요구사항

모든 진행 중 화면에서 공통으로 요구되는 실시간성:

| 화면 | 갱신 방식 | 표현 |
|------|-----------|------|
| SR 상세 | 10초 폴링 | 단계 진행 표시·서브스테이지 자동 갱신, 변화 시 부드러운 전환 |
| 장애 상세 | 10초 폴링 | 상태 레일 이동 + 산출물 슬라이드-인 |
| 스캔 상세 | 폴링 | 진행률 바 실시간 증가, finding 추가 시 목록 갱신 |
| 웹 터미널 | SSE 스트리밍 | stdout/stderr 실시간 출력 (타이핑 효과) |

**공통 애니메이션 가이드**:

- **진행 중 강조**: 현재 단계 노드에 펄스/글로우 효과 (Cyan accent)
- **상태 전이**: 단계/서브스테이지/상태 레일이 전이될 때 부드러운 이동·채움 애니메이션
- **새 항목 등장**: 이력·산출물·finding이 새로 추가될 때 슬라이드-인 또는 페이드-인
- **완료 표시**: 완료 시 ✅ 체크 + success accent로 전환 (색상 트랜지션)
- **진행률 바**: 실행 중인 작업의 경과/타임아웃을 Progress 바로 실시간 표현

## 7. 컴포넌트 구성 요약 (shadcn/ui)

화면 구현에 사용되는 컴포넌트 (참고용):

| 컴포넌트 | 용도 |
|----------|------|
| `Form` / `FormField` / `Input` / `Select` | 등록 폼 입력 |
| `Textarea` (마크다운) | 상세 내용 입력 |
| `Tag` / `Badge` | 상태·등급 배지, 멤버 태그 |
| `Table` | SR 목록, 단계 이력, 장애/스캔/규정 목록 |
| `Card` | 진행 현황 카드, 상세 섹션, 집계 카드 |
| `Button` | 등록, 액션 버튼 |
| `Dialog` | 등록 모달, 종결 모달 |
| `AlertDialog` | 트리거 주입·승격·폐기 확인 |
| `Toast` | 성공/실패 알림 |
| `Avatar` | 제출자 프로필 (GitHub avatar) |
| `Tabs` | 규정 category 5종, 자체개선 category 7종 전환 |
| `Accordion` | 장애 분석 산출물 펼침, 규정 개정 이력 |
| `Switch` | 토글 (자동 승격, enabled 등) |
| `Progress` | 상태 레일 진행도, 스캔 진행률 |
| `Command` | 규정 전역 검색 팔레트 (선택) |

## 8. 페이지 권한 매트릭스

| 페이지 | user | admin |
|--------|------|-------|
| `/login` | ✅ | ✅ |
| `/` (대시보드) | 본인 SR만 | 전체 SR |
| `/register` | ✅ | ✅ |
| `/requests/[id]` | 본인 SR | 전체 SR |
| `/admin/orgs`, `/admin/repos` | ❌ (403) | ✅ |
| `/incidents` | ✅ | ✅ |
| `/incidents/[id]` | ✅ (읽기) | ✅ (+ 승격·종결·아카이브) |
| `/incidents/inject` | ❌ (403) | ✅ |
| `/improvements` | ✅ | ✅ |
| `/improvements/[id]` | ✅ (읽기 + finding 검토) | ✅ (+ 승격 확정) |
| `/memory`, `/memory/[systemKey]` | ✅ | ✅ |
| `/memory/.../[slug]` | ✅ (읽기 + 등록·수정) | ✅ (+ 폐기) |
| `/admin/*` (템플릿·개선대상·규정시스템·토큰) | ❌ (403) | ✅ |

> **개발 규정 비대칭 권한**: 일반 사용자도 규정 등록·수정 가능. 규정을 늘리는 것은 장려, 없애는 것은 통제 원칙 — `archive`(폐기)만 admin 전용.
