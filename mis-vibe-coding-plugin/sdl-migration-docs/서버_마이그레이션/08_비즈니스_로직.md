# 09. 비즈니스 로직

## 마이그레이션 원칙 (SDP → SDL)

- ✅ 비즈니스 로직은 절대 변경하지 않고 구조/형식만 변환
- ✅ @Controller → @RestController 변환
- ✅ Model + View → ResponseEntity 변환
- ✅ @Inject → @Autowired 변환
- ✅ AbstractDAO → @Mapper 변환
- ✅ ISearchResults → List 변환
- ✅ Domain 객체 → DTO + Lombok 변환
- ✅ 변경한 부분마다 `// 변경 이유` 주석 표시
- ✅ 기존에 없던 코드 추가 시 반드시 안내

## DB 테이블 구조가 다른 경우의 추가 작업

- [ ] MyBatis Mapper XML 수정: 신 프로젝트의 DB 테이블 구조에 맞게 SQL 변경
- [ ] DTO 클래스 수정: 신 프로젝트의 DB 테이블 구조에 맞게 DTO 변경

### MyBatis Mapper XML 수정

- 구 소스의 MyBatis Mapper XML 분석
- 신 프로젝트의 DB 테이블 구조에 맞게 SQL 변경
- 테이블명, 컬럼명 변경

**구 소스 (SDP)**:

```xml
<!-- UserMapper.xml -->
<select id="selectUser" resultType="User">
    SELECT
        USER_ID,
        USER_NAME,
        USER_EMAIL
    FROM T_USER
    WHERE USER_ID = #{userId}
</select>
```

**신 프로젝트 (SDL)**:

```xml
<!-- UserMapper.xml -->
<select id="selectUser" resultType="UserDto">
    SELECT
        USER_ID,
        USER_NAME,
        USER_EMAIL
    FROM TN_CF_USER
    WHERE USER_ID = #{userId}
</select>
```

### DTO 클래스 수정

- 구 소스의 DTO 클래스 분석
- 신 프로젝트의 DB 테이블 구조에 맞게 DTO 변경
- 필드명, 타입 변경

**구 소스 (SDP)**:

```java
public class User {
    private String userId;
    private String userName;
    private String userEmail;
    
    // getters and setters
}
```

**신 프로젝트 (SDL)**:

```java
@Data
public class UserDto {
    private String userId;
    private String userName;
    private String userEmail;
    
    // Lombok이 getters and setters 자동 생성
}
```

### 2.4.2 SDP Tutorial (Entity, Service, Implement, Dao 작성)

SDP에서는 다음과 같은 순서로 비즈니스 로직을 작성합니다:

#### Entity 클래스 작성

Table 정보를 바탕으로 Domain 클래스를 생성합니다.

```java
// SDP Entity 클래스
public class Drama implements Serializable {

    private static final long serialVersionUID = 1L;
    private String dramaId;
    private String title;
    private List<DramaCharacter> dramaCharacter = new ArrayList<DramaCharacter>(0);

    public String getDramaId() {
        return dramaId;
    }

    public void setDramaId(String dramaId) {
        this.dramaId = dramaId;
    }

    public List<DramaCharacter> getDramaCharacter() {
        return dramaCharacter;
    }

    public void setDramaCharacter(List<DramaCharacter> dramaCharacter) {
        this.dramaCharacter = dramaCharacter;
    }
}
```

#### Service 클래스 작성

Service Interface 클래스를 작성합니다. Controller에서 Business Method를 호출하는 데 사용되며 signature만 작성하고 method의 구현은 Implements 클래스에서 작성합니다.

```java
// SDP Service Interface
public interface DramaService {

    ISearchResults<Drama> getPagingList(SearchVO searchVO);

    Drama get(String dramaId);

    void save(Drama drama) throws Exception;

    void update(Drama drama) throws Exception;

    void remove(String dramaId);
}
```

#### Implement 클래스 작성

DramaService의 구현 클래스인 DramaServiceImpl 클래스를 추가합니다. 비즈니스 로직은 이 단계에서 구현합니다.

```java
// SDP Service Implement
@Service                         // @Service 어노테이션을 설정합니다.
public class DramaServiceImpl implements DramaService {

    // CRUD 실행을 위해, DAO Bean을 조회할 수 있도록 합니다.
    @Inject
    DramaDao dramaDao;

    @Inject
    DramaCharacterDao dramaCharacterDao;

    // Unique한 ID를 생성하기위해 공통 서비스로 제공되고 있는 IDGenService를 조회합니다.
    @Inject
    @Named("UUIdGenerationService")
    IdGenService idGenerationService;

    public ISearchResults<Drama> getPagingList(SearchVO searchVO) {
        return this.dramaDao.getPagingList(searchVO);
    }

    public Drama get(String dramaId) {
        Drama drama = new Drama();
        drama = this.dramaDao.get(dramaId);
        drama.setDramaCharacter(dramaCharacterGetList(dramaId));
        return drama;
    }

    private List<DramaCharacter> dramaCharacterGetList(String dramaId) {
        return dramaCharacterDao.getList(dramaId);
    }

    // 트랜잭션 관리를 위한 어노테이션을 추가합니다.
    @Transactional(rollbackFor = { Exception.class }, propagation = Propagation.REQUIRED)
    public void save(Drama drama) throws Exception {

        String dramaId = idGenerationService.getNextStringId();
        drama.setDramaId(dramaId);

        dramaDao.save(drama);
    }

    @Transactional
    public void remove(String dramaId) {

        this.dramaCharacterDao.remove(dramaId);
        this.dramaDao.remove(dramaId);
    }
}
```

#### Dao 클래스 작성

DB와 연결하여 Query를 실행하기 위해, DramaDao, DramaCharacterDao 클래스를 추가합니다. 각각의 DAO를 작성할 수 있도록 AbstractDAO를 상속하여 작성합니다.

```java
// SDP DAO
@Repository("dramaDao")                         // @Repository 어노테이션을 설정합니다.
public class DramaDao extends AbstractDAO<Drama> {

    public DramaDao() {
        super(Drama.class);
    }

    // 페이지당 보여줄 데이터수를 설정합니다.
    @Value("#{contextProperties['dramaPageSize'] ?: 3}")
    int pageSize;

    // 네비게이션에 보여줄 페이지수를 설정합니다.
    @Value("#{contextProperties['dramaPageUnit'] ?: 10}")
    int pageUnit;

    // AbstractDAO에서 제공하는 기능을 이용하여 쿼리를 실행합니다.
    public ISearchResults<Drama> getPagingList(SearchVO searchVO) {

        String searchCondition = StringUtil.null2str(searchVO.getSearchCondition());
        String searchKeyword = StringUtil.null2str(searchVO.getSearchKeyword());

        Map<String, Object> arg = new HashMap<String, Object>();
        arg.put("searchCondition", searchCondition);
        arg.put("searchKeyword", searchKeyword);

        ISearchResults<Drama> searchResult = selectBy(arg, searchVO.getPageIndex(), pageSize, pageUnit, "");
        return searchResult;
    }
}
```

#### SDL 변환 시 주의사항

- **@Inject → @Autowired**: SDP에서는 `@Inject`를 사용하지만, SDL에서는 `@Autowired`를 사용
- **AbstractDAO → @Mapper**: SDP에서는 `AbstractDAO`를 상속받지만, SDL에서는 `@Mapper`를 사용
- **@Service, @Repository**: SDP와 SDL 모두 동일하게 사용
- **@Transactional**: SDP와 SDL 모두 동일하게 사용
- **ISearchResults → List**: SDP에서는 `ISearchResults`를 사용하지만, SDL에서는 `List`를 사용
