## 마이그레이션 원칙

✅ **비즈니스 로직은 절대 변경하지 않고 구조/형식만 변환**
✅ **변경한 부분마다 `// 변경 이유` 주석 표시**
✅ **기존에 없던 코드 추가 시 반드시 안내**
✅ **신규 DEMO 플랫폼 패턴/방식 기준**
✅ **신규 개발 DB 스키마(SDL 표준)에 맞게 개발**

## 비즈니스 로직 유지 원칙

### ✅ 해야 할 것

1. **비즈니스 로직 유지**
   - 기존 비즈니스 로직은 변경하지 않고 플랫폼만 변환
   - 기능 추가는 마이그레이션 완료 후 진행

2. **구조/형식 변환**
   - Spring 3.0 → Spring Boot 3.5.8
   - iBATIS2 → MyBatis 3.x
   - JSP → Vue.js 3 SPA
   - SDP 라이브러리 → SDL 프레임워크

3. **주석 표시**
   - 변경한 부분마다 `// 변경 이유` 주석 표시
   - 기존에 없던 코드 추가 시 반드시 안내

### ❌ 하지 말아야 할 것

1. **비즈니스 로직 변경**
   - 기존 비즈니스 로직을 변경하지 않음
   - 기능 추가는 마이그레이션 완료 후 진행

2. **데이터 구조 변경**
   - 기존 데이터 구조를 변경하지 않음
   - SDL 표준 DB 스키마에 맞게 개발

3. **API 인터페이스 변경**
   - 기존 API 인터페이스를 변경하지 않음
   - REST API로 변환 시 기존 기능 유지

## 신규 DEMO 플랫폼 패턴/방식 기준

### Controller 패턴

```java
// 신규 DEMO 패턴
@RestController
@RequestMapping("/api/user")
public class UserController {
    
    @Autowired
    private UserService userService;
    
    @GetMapping("/list")
    public ResponseEntity<List<UserDto>> list(UserDto user) {
        List<UserDto> list = userService.getList(user);
        return ResponseEntity.ok(list);
    }
}
```

### Service 패턴

```java
// 신규 DEMO 패턴
@Service
public class UserServiceImpl implements UserService {
    
    @Autowired
    private UserMapper userMapper;
    
    @Transactional
    public List<UserDto> getList(UserDto user) {
        return userMapper.getList(user);
    }
}
```

### Mapper 패턴

```java
// 신규 DEMO 패턴
@Mapper
public interface UserMapper {
    List<UserDto> getList(UserDto user);
}
```
