F-1 · 승인 전 확인 필요

AuthGuard가 서버간 인증 스킴을 다 덮지 못한다

AD-2는 AuthGuard를 모든 인증의 단일 검증 지점으로 정했고, 컴포넌트 정의는 “서버간 인증 4종”을 전제로 7개 함수를 선언했다. 그런데 명세에서 실제로 살아 있는 스킴을 세어 보니 그보다 많았다.

스킴쓰이는 곳AuthGuard 함수상태
SDLC_MASTER_KEY내부 API 다수 (/intake · /advance)requireMasterKey덮음
POD_AUTH_TOKENPod Runner 호출requirePodToken덮음
sdlcmem_*MCP BearerrequireMemoryToken덮음
이미지 서명GET /images/{id}signImageUrl · verifyImageToken덮음
SDLC_RECONCILE_TOKENCronJob → reconcile—누락
SDLC_CALLBACK_BEARERPod · n8n → channel-notification—누락
SDLC_MEMORY_TOKEN_ISSUER_TOKENMCP 토큰 발급 권한 분리의 근거—누락
SLACK_SIGNING_SECRETevents-api 모드 전용 (gateway 모드 미사용)—조건부

제안 — Step 4에서 7함수 → 10함수

requireReconcileToken() · requireCallbackBearer() · requireTokenIssuer() 를 추가하고 components.md의 C-1.2 정의를 갱신한다. 이 계획을 승인하면 그 갱신도 함께 승인된다.

일부러 만들지 않는 것 둘

SLACK_SIGNING_SECRET — events-api 모드에서만 필요한데 설계는 gateway 모드를 쓴다. 쓰지 않을 검증 코드를 미리 만들지 않고 주석만 남긴다.

SDLC_INCIDENT_INGEST_TOKEN — 명세가 Master Key로 통합하며 제거하고 그로 인한 잔존 위험까지 기록해 둔 항목이다. 되살리지 않는다.
